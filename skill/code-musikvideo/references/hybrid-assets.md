# Hybrid assets

Use supplied or generated raster layers when they serve the accepted treatment. Code-only production remains available. Verify the image-generation or editing capability before promising new assets; a skill does not install a generator.

## Divide responsibilities

Use images for material, texture, atmosphere and objects when that improves the result. Keep required exact lettering, labels, counts, equations and interface geometry in code or verified source artwork. Generated equations are decorative until independently checked. Illustrated flow is not a numerical simulation, and neither establishes a mathematical proof.

Record each asset's job and what animation will change. Request separate foreground objects, text-free backgrounds, transparency or alternate object states only when the composition needs them. A concept reference is not automatically a production-ready layer.

## Preserve identity across assets

Use an accepted asset as the editing reference when its identity must survive a state change. Preserve relevant silhouette, orientation, lighting, viewpoint and material. Inspect the generated result before continuing. Include enough transparent margin for planned motion and check the edge treatment against the delivery background.

Retain original inputs and generated source assets with prompts or editing instructions, provenance and hashes where the project records them. Version source layers or preserve another recoverable backup. Store rendered frames and disposable conversions as reproducible outputs. Update public attribution when the production changes from code-only to hybrid.

## Prepare immutable runtime sources

Await image decoding and font readiness before declaring the scene ready. Prepare reusable graphics independently of the first requested time. Use the actual player's verified same-origin loopback or embedded-image path. Do not assume a classic file player supports module loading or raster decoding.

Keep the source for drawing constant across frames. A browser may change scaled image decoding when the same PNG is used as a full object and differently scaled crops. In the Jagged rupture this produced different pixels after seeking despite deterministic drawing commands. A single native-resolution raster copy during preparation resolved that case. Treat this as a remedy to verify for an observed mismatch, rather than a mandatory conversion for every image.

## Check production states

Compare decoded pixels for an asset's first use, a changed state, a different time, return to the first state and a fresh context. Check the actual full-object and cropped uses. Command-level determinism alone does not test image decoding.

Inspect state changes in a short clip before the full export. Preserve a source object until its intended transformation event, and check that camera movement or deformation does not create an unintended earlier state. Missing required assets or measurements must produce a visible failure. Keep independently available text or source material accessible in the preview when media loading fails.
